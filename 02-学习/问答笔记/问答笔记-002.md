# 问答笔记-002

## 1. Python 什么时候用驼峰命名、什么时候用下划线命名？

**回答**：

Python 命名规范（PEP 8）很明确，**除了类名用 PascalCase、常量用全大写，其余全部 snake_case，没有 camelCase 的位置。**

| 类型 | 风格 | 举例 |
|------|------|------|
| 变量 / 函数 / 方法 | `snake_case` | `user_name`, `get_data()` |
| 类 | `PascalCase` | `HttpClient`, `MyModel` |
| 常量 | `UPPER_SNAKE_CASE` | `MAX_SIZE`, `PI` |
| 模块 / 包 | `snake_case` | `feature_matching`, `data_loader.py` |
| 私有属性/方法 | `_` 前缀 + `snake_case` | `_internal_state`, `_compute()` |
| 魔术方法 | `__` 双下划线包裹 | `__init__`, `__str__` |
| 名称修饰(name mangling) | `__` 前缀 + `snake_case` | `__private_var`（子类无法直接访问） |

**易混淆点：**
- 类实例的属性也是 `snake_case`，不要因为类是 PascalCase 就把属性写成驼峰
- 枚举成员用 `UPPER_SNAKE_CASE`（本质是常量）：`Color.RED`, `Status.HTTP_OK`
- 异常类是类，用 PascalCase：`ValueError`, `CustomNetworkError`

**一句话：除了类名用 PascalCase、常量用全大写，其余全部 snake_case。**

## 2. Java 中的命名规范是什么？和 Python 有什么区别？

**回答**：

Java 的命名规范和 Python 有明显区别，**驼峰（camelCase）在 Java 里是主力**。

| 类型 | 风格 | 举例 |
|------|------|------|
| 类 / 接口 | `PascalCase` | `HttpClient`, `Runnable` |
| 方法 | `camelCase` | `getData()`, `calculateLoss()` |
| 变量 | `camelCase` | `userName`, `batchSize` |
| 常量 | `UPPER_SNAKE_CASE` | `MAX_SIZE`, `DEFAULT_TIMEOUT` |
| 包名 | 全小写（不用下划线） | `com.example.feature` |
| 泛型类型参数 | 大写单字母 | `T`, `E`, `K`, `V` |

**Python vs Java 关键对比：**

| 类型 | Python | Java |
|------|--------|------|
| 变量 | `snake_case` | `camelCase` |
| 函数/方法 | `snake_case` | `camelCase` |
| 类 | `PascalCase` | `PascalCase` |
| 常量 | `UPPER_SNAKE_CASE` | `UPPER_SNAKE_CASE` |
| 包/模块 | `snake_case` | 全小写无分隔 |

**Java 特有要点：**
- Java 用 `private` 关键字控制访问，不需要像 Python 那样用 `_` 前缀表示私有
- 布尔变量用 `is`/`has`/`can` 开头：`isValid`, `hasPermission`
- getter/setter 遵循 JavaBeans：`getName()` / `setName()`，布尔型 `isValid()` / `setValid()`
- 枚举值用 `UPPER_SNAKE_CASE`：`HttpStatus.NOT_FOUND`

**一句话：Java 除类名 PascalCase、常量全大写外，其余变量方法一律 camelCase。没有 snake_case 的位置。**
